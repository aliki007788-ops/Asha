# معماری آشا (ASHA Architecture)

**نسخه مستند:** 0.1.0  
**تاریخ:** 2026-09-14

## نمای کلی

آشا از ۵ لایه تشکیل شده است:

```
لایه ۱: هسته آشا (ASHA Core)
  Orchestrator | Registry | Config | State | Event Bus

لایه ۲: ایجنت‌های اصلی (۱۵ ایجنت مشتری‌رو)
  Sales Closer | Outbound | Sequencer | Proposal | Upsell | ...

لایه ۳: ایجنت‌های پشتیبان (۱۰ ماژول)
  Adapter | Memory | Analytics | Pricing | Auth | Queue | ...

لایه ۴: لایه اتصال چندپلتفرمی (Adapter Layer)
  Eitaa | Bale | Rubika | Divar | Torob | Emalls | Bridge ...

لایه ۵: پلتفرم‌های بیرونی
  ایتا | بله | روبیکا | دیوار | ترب | ایمالز | تلگرام | اینستاگرام
```

## اصول طراحی

1. **استقلال ایجنت‌ها** — خرابی یک ایجنت بقیه را متوقف نمی‌کند.
2. **لایه اتصال واحد** — افزودن پلتفرم جدید فقط نیاز به Adapter جدید دارد.
3. **Plugin-based** — ایجنت جدید بدون تغییر هسته اضافه می‌شود.
4. **تک‌نسخه‌ای بودن** — هر فایل فقط یک نسخه کامل دارد.

## هسته (Core)

- **Orchestrator**: هماهنگی وظایف و ارجاع به ایجنت‌ها
- **Registry**: Service Discovery برای ایجنت‌ها
- **Config**: تنظیمات صنفی و محیطی
- **State**: مدیریت وضعیت وظایف
- **Event Bus**: ارتباط غیرهمزمان (فعلاً in-memory، بعداً Redis Streams)

## جریان یک وظیفه نمونه

1. درخواست از API یا Adapter وارد می‌شود.
2. Orchestrator وظیفه را در State ثبت می‌کند.
3. رویداد `system.task` روی Event Bus منتشر می‌شود.
4. ایجنت مربوطه وظیفه را اجرا می‌کند.
5. نتیجه در State ذخیره و در صورت نیاز پاسخ ارسال می‌شود.
